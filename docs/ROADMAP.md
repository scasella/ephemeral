# Quality-of-life roadmap

## Completed priorities — fourth end-user UI/UX panel

Six fresh GPT-6 Astra agents with low reasoning effort reviewed the app visually and interactively, then challenged one another's rankings. These are simulated end-user perspectives. Fresh evidence supports changes to state clarity, focus, copy and layout; see [the audit and limits](VALIDATION.md).

| Priority | Modification | First useful scope |
|---|---|---|
| 1 | State-aware survival and cleanup summaries | Implemented: recovery language, scoped dated published evidence, own/inherited saved handoff presence, historical local diagnostics and independent cleanup with prominent unverified remote Codex state. See [local verification](VALIDATION.md). |
| 2 | Keyboard continuity and useful detail jumps | Implemented: focus after history selection/reselection, explicit selection announcement, interruption guards and useful detail alignment at desktop and 640×400. See [local verification](VALIDATION.md). |
| 3 | Consistent survival and service feedback | Implemented: commit **and push** at sign-in, explicit initial lifetime, configured-state guidance, wait/retry copy, independently dated configuration/session/repository reads, and completion ordering that preserves newer failures. See [local verification](VALIDATION.md). |
| 4 | Compact workspace and review surface | Implemented: one selected-machine header, reachable terminal Focus controls, compact PR links and exact-review disclosures, concise saved/empty Notes with explicit editing, preserved draft/conflict recovery, and safe terminal unmount on machine switches. See [local verification](VALIDATION.md). |
| 5 | Visible Preview sequence and relevant unavailable states | Implemented: four explicit steps and overview, contextual shell access and framework help, optional readiness, renewal/close consequences, lifecycle-specific reasons and guarded recovery. See [local verification](VALIDATION.md). |

All five priorities are implemented. Factual history handoff cues remain follow-ups; a stored PR or old check must not imply current resume readiness. Scope a pre-sign-in permission disclosure only after verifying the actual permission flow. Priority 5 reverified real React/Vite HMR through the production gateway and viewer locally with synthetic identity/provider adapters; real provider-side cleanup was not reverified. No deployment or paid hosting change is authorized by this roadmap.

## Completed priorities — third end-user panel

Six fresh GPT-6 Astra agents, each using low reasoning effort, independently reviewed the current app and then challenged one another's recommendations. Perspectives covered a newcomer, frontend freelancer, low-vision keyboard user, private-code maintainer, open-source reviewer, and budget-conscious founder. These are simulated reviews, not customer interviews. See [evidence, deliberation, and proposed scopes](VALIDATION.md).

This was the recommended shipping order, balancing the panel's votes with implementation size and risk. All five priorities are implemented.

| Priority | Feature | First useful release |
|---|---|---|
| 1 | Expiry reminders outside the selected machine view | Implemented: global 10-minute/two-minute warnings, opt-in desktop alerts with cross-tab coordination, and return to save guidance. See [verification](VALIDATION.md). |
| 2 | Durable next-session handoff notes | Implemented: revisioned plain-text notes with saved time, conflict recovery, and immutable inherited notes on continuation. See [verification](VALIDATION.md). |
| 3 | A readable workspace that keeps active work easy to reach | Implemented: larger text, collapsible history/status, keyboard skip links, dialog focus recovery, exact-machine return links, and verified 200% zoom reflow. See [verification](VALIDATION.md). |
| 4 | Review published changes before PR handoff | Implemented: bounded pushed-file review, exact head/base/merge-base IDs, ended-machine access, and rejection of changed reviewed branches before PR creation. See [verification](VALIDATION.md). |
| 5 | Preview readiness diagnostics and proven framework HMR | Implemented: explicit bounded application response checks with port/status/time and remedies; real React/Vite HMR preserves component state through private preview. Server startup stays explicit. See [verification](VALIDATION.md). |

An explicit reviewed commit-and-push flow received strong panel support. Design it as the next larger project while these smaller slices ship: exact file selection, changed-work rejection, explicit execution, and distinct local-commit versus remote-confirmation outcomes. Do not treat it as a generic save-all button.

Application cookies, a browser editor, shorter explicit lifetimes, retained-content controls, and commit-bound test results remain candidates. Retention policy, accurate cleanup evidence, and actual keyboard accessibility are pilot release concerns, independently of feature voting.
