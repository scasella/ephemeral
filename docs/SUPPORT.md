# Support and security contact draft

Status: contact setup pending at the owner's request. No support/security address or response-time commitment is active. A GitHub noreply commit address is not a support inbox. Do not republish a maintainer's personal address as a substitute.

## Proposed pilot process

Before inviting hosted users, configure a role inbox or private ticket channel, verify receipt and reply from an outside account, restrict operator access, and publish the working route in SECURITY and the application help. Exercise routine support, deletion requests and an urgent cleanup/security report. Confirm owner/account identity without requesting passwords, tokens or device codes.

Proposed triage targets are one business day for acknowledgement and immediate operator review of suspected unauthorized access or unresolved billable resources. These are draft targets, not an SLA or a statement that monitoring is staffed. The owner must adopt realistic coverage before activation.

Ordinary reports should include version, mode, affected feature, expected/observed behavior and a short sanitized error. Handle vulnerabilities, private repository content and deletion requests privately. Do not request `.env`, PEMs, auth caches, browser cookies, raw setup/terminal transcripts or capability receipts. Operators may request a narrowly scoped status result through a private channel.

## Urgent session/credential problems

Stop the affected machine through the application, inspect every cleanup outcome and retry unresolved phases. If the only control plane is unavailable, the operator must independently inspect provider resources and upstream credentials, preserve recovery state and reconcile before service resumes. Do not erase the database/key or private cleanup evidence to hide a failure.

Local Codex logout and VM destruction do not establish remote account-token revocation. Tell users what has and has not been verified. Direct upstream account actions through the provider's official interface and record outcomes without copying credentials into support.

## Publication gate

Select/test the private route before public source announcement, enable and test GitHub private vulnerability reporting when an authorized public repository exists, and replace the pending statements only after those routes work. Public GitHub issues must not become the fallback for sensitive reports.
